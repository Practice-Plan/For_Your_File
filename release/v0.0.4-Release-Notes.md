## Changelog

### 🐛 Bug Fixes

#### 1. Enter Key Interception — Accidental "Open Confirmation" in Notes and Search Bar
- **Issue**: Pressing Enter in the project notes textarea failed to insert a line break; pressing Enter in the search bar triggered an incorrect "Open Confirmation" dialog.
- **Root Cause**: The global keyboard shortcut handler and the `SearchResults` Enter-key interception logic failed to check if `document.activeElement` was an INPUT or TEXTAREA element.
- **Fixes**:
	- `SearchResults.tsx`: Added an `isInputFocused` check to skip interception when focus is on an INPUT or TEXTAREA.
	- `useKeyboardShortcuts.ts`: Added the same guard condition to the global keyboard handler.
- **Files**: `src/components/SearchResults.tsx`, `src/hooks/useKeyboardShortcuts.ts`

#### 2. Database Preview — Infinite Loading / Theme Errors / Language Sync Issues
- **Issue**: The standalone DatabasePreview window had three bugs:
	1. It remained stuck on "Loading" upon initial opening.
	2. The theme was always light (it bypassed the main window's `applyTheme` process).
	3. The preview window did not update when the language was changed.
- **Root Causes**:
	1. `loadTable` used `useCallback` with a dependency on the `isLoading` state, creating a loop: state change → function recreation → `useEffect` re-trigger → new request.
	2. DatabasePreview runs in a separate Tauri webview and bypassed the `applyTheme` logic in `App.tsx`.
	3. Each Tauri window is an independent webview; i18n state was not shared.
- **Fixes**:
	1. Replaced the `isLoading` state with `isLoadingRef` for concurrency guarding and set the `useCallback` dependency array to `[]`.
	2. Read `app-theme` from `localStorage` on mount and applied the `.dark` class; added a listener for the `storage` event to sync theme changes from the main window.
	3. Added a listener for the `storage` event to detect when the main window updates `i18nextLng`, then automatically calls `i18n.changeLanguage()`.
- **File**: `src/components/DatabasePreview.tsx`

#### 3. PPC terminated after startup
- **Issue**: The PPC process is terminated some time after starting in the background (usually when the parent process's Job object is cleaned up).
- **Root Cause**: Windows Job Object mechanism. Tauri applications run within a Job object, and child processes are bound to the parent's Job by default. When the parent's Job closes, all child processes are terminated along with it. Using only `CREATE_NO_WINDOW` was insufficient.
- **Fix**: Changed the creation flags from the single `CREATE_NO_WINDOW (0x08000000)` to a combination of three flags:
```text
CREATE_NO_WINDOW          = 0x08000000  // Do not create a console/taskbar window
DETACHED_PROCESS          = 0x00000008  // Do not attach to the parent process's console
CREATE_NEW_PROCESS_GROUP  = 0x00000200  // Crucial — Create an independent process group, detaching from the parent process's Job
```
The PPC now operates as a fully independent daemon process, unaffected by the parent process's lifecycle.

- **File**: `src-tauri/src/ppc_linker.rs` — `launch_installed_ppc_as_user()`

### ✨ Feature Improvements

#### 4. PPC Connection — "Try-Launch-Try" + 5-Minute Continuous Retry
- **Previous**: Quick ping → Unreachable → Launch PPC → Wait 10s → 3 retries → Error on failure
- **Current**: "Try-Launch-Try" mode with continuous TCP probing (once per second) for 5 minutes (300s):
	1. Quick ping (2s timeout)
	2. Unreachable → Launch PPC in background (window completely hidden)
	3. Enter `wait_for_port` loop, attempting connection once per second
	4. Connection established within 5 minutes → Version check → Registration → Authentication
	5. Still unreachable after 5 minutes → Detailed error report
- **Use Cases**: Slow machines, PPC startup delays due to resource constraints, high system load
- **Files**: `src-tauri/src/ppc_linker.rs` — `ppc_connect_auto()`, `wait_for_port()`

#### 5. Search Caching System
- **Previous**: No caching; re-queried on every search; "Load More" prone to hanging under resource constraints
- **Current**: Full LRU cache + stale-while-revalidate strategy:
	- 50 cache entries, 5-minute TTL
	- 30s request timeout, 3 retries with exponential backoff
	- `invalidateCache()` method to refresh data after changes
	- `mountedRef` to prevent `setState` calls after component unmount
- **File**: `src/hooks/useSearch.ts`

#### 6. Reduced CPU Usage
- **Root Cause**: Global hotkey message loop in `hotkey.rs` had a sleep interval of only 10ms, causing 100 `PeekMessageW` calls and `try_recv` wake-ups per second during idle time
- **Fix**: Increased sleep interval from 10ms to 50ms (20 iterations per second)
- **Result**: Hotkey response latency increased from an average of 5ms to 25ms (imperceptible to users), while idle CPU usage dropped by approximately 80%.
- **File**: `src-tauri/src/hotkey.rs`

#### 7. Frontend Build — Eliminated "chunk too large" warning; initial load speed improved by 78%
- **Issue**: `vite build` output a single 522 kB chunk, triggering the warning: "Some chunks are larger than 500 kB after minification."
- **Root Cause**: Static imports for all components prevented Rollup from establishing chunk boundaries.
- **Fixes**:
	1. **React.lazy dynamic imports**: Switched 8 infrequently used components (EntryDetail, AddEntryModal, BatchImportModal, CreateGroupModal, EditGroupModal, AboutModal, HotkeySettings, InterfaceShortcutSettings) to on-demand loading.
	2. **manualChunks splitting**: Created vendor chunks for React, Framer, i18n, and Tauri.
	3. **Suspense fallback={null}**: Eliminated UI flickering during lazy loading.
- **Results**:

| Metric | Before | Now | Improvement |
|------|------|------|------|
| Chunk count | 1 | 17 | — |
| Largest chunk | 522 kB ⚠️ | 143 kB ✅ | -73% |
| Main entry (index.js) | 522 kB | 116 kB | **-78%** |
| Warnings | Yes | No | Eliminated |

- **Files**: `src/App.tsx`, `vite.config.ts`

### 🔧 Project Configuration

#### 11. CI Simplification — Checks + Build Tests (No Packaging)
- **Before**: Two separate jobs (test + build), including artifact uploads.
- **Now**: A single `check` job performing only: TypeScript type-check → cargo test → cargo clippy → cargo fmt --check → cargo build --release.
- Eliminated the packaging/installer creation and artifact upload steps.
- **File**: `.github/workflows/ci.yml`

#### 12. Disable EXE installer + Optimize bundling
- Set `"bundle.active": false` and `"targets": []` in `tauri.conf.json`.
- Removed the `wix` (MSI installer) configuration block.
- Retained the icon array (icons still need to be embedded during compilation).
- **File**: `src-tauri/tauri.conf.json`

#### 13. Version Synchronization
- `package.json`: 0.0.3 → 0.0.4
- `src-tauri/Cargo.toml`: 0.0.3 → 0.0.4
- `src-tauri/tauri.conf.json`: 0.0.3 → 0.0.4
- Updated version synchronization checks in the CI workflow.

## Upgrade Instructions

1. Download the new version executable file (v0.0.4)
2. Directly replace the old version (no database migration, no configuration format changes)
3. PPC connection will automatically adapt to the new version on first startup: Try-Launch-Try process.
4. There will be a slight delay when the search function is used for the first time (cold caching), which will speed up afterwards.

**Backward Compatibility**: ✅ Fully backward compatible. Database schema unchanged, configuration file format unchanged, PPC protocol unchanged.
