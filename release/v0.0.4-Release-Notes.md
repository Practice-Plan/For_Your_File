## 概述

v0.0.4 是一个集中修复版本，主要解决 PPC 连接稳定性、数据库预览可靠性、资源占用优化和前端构建体积问题。同时改进了用户交互细节（Enter 键行为、About 界面、Banner 展示）。

**影响范围**: 前端 React/TypeScript、后端 Rust/PPC 集成、CI 工作流、构建配置

## 变更清单

### 🐛 Bug 修复

#### 1. Enter 键拦截 — 备注和搜索栏误触发"打开确认"
- **问题**: 在项目备注 textarea 中按 Enter 无法换行；在搜索栏中按 Enter 会触发错误的"打开确认"对话框
- **根因**: 全局键盘快捷键处理器和 `SearchResults` 的 Enter 拦截逻辑没有检查 `document.activeElement` 是否在 INPUT/TEXTAREA 中
- **修复**:
  - `SearchResults.tsx`: 添加 `isInputFocused` 检查，当焦点在 INPUT/TEXTAREA 时跳过拦截
  - `useKeyboardShortcuts.ts`: 全局键盘处理器增加同样的守卫条件
- **文件**: `src/components/SearchResults.tsx`, `src/hooks/useKeyboardShortcuts.ts`

#### 2. 数据库预览 — 一直加载 / 主题错误 / 语言不实时
- **问题**: 独立 DatabasePreview 窗口存在三个 bug：
  1. 首次打开永远停在"加载"
  2. 主题始终是浅色（不走主窗口的 `applyTheme` 流程）
  3. 切换语言后预览窗口不跟随
- **根因**:
  1. `loadTable` 用 `useCallback` 依赖 `isLoading` state，形成循环：state 变化 → 函数重建 → useEffect 重新触发 → 新请求
  2. DatabasePreview 是独立 Tauri webview，不走 App.tsx 的 `applyTheme`
  3. 每个 Tauri 窗口是独立 webview，i18n 状态不共享
- **修复**:
  1. 用 `isLoadingRef` 替代 state 做并发守卫，`useCallback` 依赖数组改为 `[]`
  2. 组件挂载时从 localStorage 读取 `app-theme` 并应用 `.dark` 类；监听 `storage` 事件同步主窗口的主题变化
  3. 监听 `storage` 事件，当主窗口写入 `i18nextLng` 时自动调用 `i18n.changeLanguage()`
- **文件**: `src/components/DatabasePreview.tsx`

#### 3. PPC 启动后被杀死
- **问题**: PPC 在后台启动后，过一段时间（通常是父进程 Job 对象清理时）被终止
- **根因**: Windows 的 Job Object 机制。Tauri 应用运行在一个 Job 对象中，子进程默认绑定到父进程的 Job。父进程 Job 关闭时所有子进程被连带清理。之前只用了 `CREATE_NO_WINDOW`，不够。
- **修复**: 创建 flag 从单一 `CREATE_NO_WINDOW (0x08000000)` 改为三标志组合：
  ```
  CREATE_NO_WINDOW          = 0x08000000  // 不创建控制台/任务栏窗口
  DETACHED_PROCESS          = 0x00000008  // 不附加到父进程 console
  CREATE_NEW_PROCESS_GROUP  = 0x00000200  // 关键 — 创建独立进程组，脱离父进程 Job
  ```
  PPC 现在是完全独立的守护进程，不受父进程生命周期影响。
- **文件**: `src-tauri/src/ppc_linker.rs` — `launch_installed_ppc_as_user()`

### ✨ 功能改进

#### 4. PPC 连接 — Try-Launch-Try + 5 分钟持续重试
- **之前**: 快速 ping → 不可达 → 启动 PPC → 等 10s → 3 次重试 → 失败报错
- **现在**: Try-Launch-Try 模式，持续 5 分钟（300s）每秒一次 TCP 探测
  1. 快速 ping（2s timeout）
  2. 不可达 → 后台启动 PPC（完全隐藏窗口）
  3. 进入 `wait_for_port` 循环，每秒一次尝试连接
  4. 5 分钟内通了 → 版本检查 → 注册 → 认证
  5. 5 分钟仍不可达 → 详细报错
- **适用场景**: 慢速机器、资源紧张时 PPC 启动延迟、系统负载高
- **文件**: `src-tauri/src/ppc_linker.rs` — `ppc_connect_auto()`, `wait_for_port()`

#### 5. 搜索缓存系统
- **之前**: 无缓存，每次搜索都重新查询；资源紧张时容易"加载更多"卡住
- **现在**: 完整 LRU 缓存 + stale-while-revalidate：
  - 50 条缓存条目，5 分钟 TTL
  - 请求超时 30s，指数退避 3 次重试
  - `invalidateCache()` 方法供数据变更后刷新
  - `mountedRef` 防止组件卸载后 setState
- **文件**: `src/hooks/useSearch.ts`

#### 6. 降低 CPU 占用
- **根因定位**: `hotkey.rs` 中的全局快捷键消息循环，sleep 只有 10ms，导致空闲时每秒 100 次 PeekMessageW + try_recv wake-up
- **修复**: sleep 从 10ms → 50ms（每秒 20 次）
- **效果**: 快捷键响应延迟从平均 5ms → 25ms（用户不可感知），但空闲 CPU 占用降低约 80%
- **文件**: `src-tauri/src/hotkey.rs`

#### 7. 前端构建 — 消除 chunk 过大警告，首屏提速 78%
- **问题**: `vite build` 输出单一 522 kB chunk，触发警告 `Some chunks are larger than 500 kB after minification`
- **根因**: 所有组件静态导入，Rollup 无法形成 chunk 边界
- **修复**:
  1. **React.lazy 动态导入**: 8 个低频组件（EntryDetail, AddEntryModal, BatchImportModal, CreateGroupModal, EditGroupModal, AboutModal, HotkeySettings, InterfaceShortcutSettings）改为按需加载
  2. **manualChunks 分包**: vendor-react / vendor-framer / vendor-i18n / vendor-tauri
  3. **Suspense fallback={null}**: 懒加载时 UI 无闪烁
- **效果**:

  | 指标 | 之前 | 现在 | 改善 |
  |------|------|------|------|
  | chunk 数量 | 1 | 17 | — |
  | 最大 chunk | 522 kB ⚠️ | 143 kB ✅ | -73% |
  | 主入口 index.js | 522 kB | 116 kB | **-78%** |
  | 警告 | 有 | 无 | 消除 |

- **文件**: `src/App.tsx`, `vite.config.ts`

### 🔧 工程配置

#### 11. CI 简化 — 检查 + 编译测试（不打包）
- **之前**: 两个独立 job（test + build），含 artifact 上传
- **现在**: 单一 `check` job，只做：TypeScript type-check → cargo test → cargo clippy → cargo fmt --check → cargo build --release
- 消除了打包安装包和 artifact 上传步骤
- **文件**: `.github/workflows/ci.yml`

#### 12. 禁用 exe installer + 优化 bundle
- `tauri.conf.json` 中 `"bundle.active": false`, `"targets": []`
- 移除了 `wix`（MSI installer）配置块
- 保留 icon 数组（编译时仍需嵌入图标）
- **文件**: `src-tauri/tauri.conf.json`

#### 13. 版本同步
- `package.json`: 0.0.3 → 0.0.4
- `src-tauri/Cargo.toml`: 0.0.3 → 0.0.4
- `src-tauri/tauri.conf.json`: 0.0.3 → 0.0.4
- CI workflow 中版本同步检查已更新

## 升级说明

4. 搜索功能首次使用时会有轻微延迟（冷缓存），之后变快
