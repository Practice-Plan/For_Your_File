# Руководство по созданию пакетов компонентов

Начиная с v0.0.5 функции For_Your_File организованы в виде **пакетов компонентов (Component Package)**. Пакет компонентов — это обычный JSON-документ, объявляющий конфигурацию набора функций; хост читает и интерпретирует эту конфигурацию и **никогда не загружает и не выполняет сторонний код**, поэтому импорт пакетов, созданных другими, безопасен.

Этот документ также служит источником для встроенного «Руководства по созданию» (команда `get_component_creation_guide` возвращает этот файл).

---

## 1. Структура файла

Пакет компонентов — это просто файл с расширением `.json`:

```json
{
  "schema": 1,
  "id": "com.example.my-pack",
  "name": "我的组件包",
  "version": "1.0.0",
  "description": "一句话说明这个组件包做什么",
  "author": "你的名字",
  "kind": "theme",
  "components": [
    {
      "id": "appearance",
      "kind": "theme",
      "title": "我的配色",
      "config": { "accent": "violet" }
    }
  ]
}
```

## 2. Поля

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `schema` | Да | Версия формата, сейчас фиксирована `1` |
| `id` | Да | Уникальный идентификатор. 3–64 символа; первый — буква или цифра, остальные могут быть `a-z`, `0-9`, `.`, `-`, `_`. Рекомендуется форма `com.автор.имя` |
| `name` | Да | Отображаемое имя, 1–100 символов |
| `version` | Да | Числа через точку, например `1.0.0` (1–4 сегмента, только цифры) |
| `description` | Нет | Описание |
| `author` | Нет | Сведения об авторе |
| `kind` | Нет | Тип пакета, см. ниже; пустое значение — универсальный пакет |
| `components` | Нет | Массив компонентов, не более 32 |

### Объект компонента

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `id` | Да | Идентификатор компонента, 1–64 символа |
| `kind` | Да | Тип компонента, по нему хост выбирает способ интерпретации |
| `title` | Да | Заголовок компонента (для интерфейса) |
| `config` | Нет | Произвольный JSON-объект, не более 256 КиБ после сериализации |

## 3. Типы пакетов (kind)

| kind | Назначение |
| --- | --- |
| `theme` | Внешний вид: цвет акцента, размер шрифта, анимация и другие параметры отображения |
| `search` | Поведение поиска: стратегия сортировки, размер страницы, многоязычный режим |
| `workflow` | Быстрые действия: объединение существующих команд в кнопки действий |
| `bundle` | Комбинированный пакет: содержит компоненты нескольких типов одновременно |

## 4. Соглашения о конфигурации

Хост читает `config` в соответствии с `kind` компонента. Ниже перечислены распознаваемые сейчас ключи (неизвестные ключи игнорируются и зарезервированы для будущих версий):

### 4.1 `theme`

```json
{ "accent": "blue", "font_scale": "normal", "reduce_motion": false }
```

| Ключ | Значения | Описание |
| --- | --- | --- |
| `accent` | `blue` `violet` `emerald` `amber` `rose` | Цвет акцента |
| `font_scale` | `small` `normal` `large` | Размер шрифта интерфейса |
| `reduce_motion` | `true` / `false` | Уменьшить анимацию |

### 4.2 `search`

```json
{ "sort": "relevance", "page_size": 50, "multilingual": true }
```

| Ключ | Значения | Описание |
| --- | --- | --- |
| `sort` | `relevance` `mostUsed` `recentlyOpened` `alphabetical` | Сортировка по умолчанию |
| `page_size` | Целое число от 10 до 200 | Результатов на странице |
| `multilingual` | `true` / `false` | Включить поиск по подстроке для не-ASCII ключевых слов (CJK, кириллица, арабский и т. д.) |

### 4.3 `workflow`

```json
{
  "actions": [
    { "id": "rebuild-index", "title": "重建搜索索引", "command": "rebuild_fts_index" }
  ]
}
```

`command` должен быть именем команды, уже зарегистрированной хостом (например, `open_database_preview`, `rebuild_fts_index`). Неизвестные команды не выполняются, а только отображаются в отключённом состоянии.

## 5. Импорт, экспорт и встроенные пакеты

- **Импорт**: Настройки → Пакеты компонентов → Импорт, затем выберите файл `.json`. Проверяются schema, id, версия, kind, число компонентов и размер конфигурации; некорректный пакет отклоняется с указанием причины.
- **Экспорт**: любой пакет (включая встроенный) можно экспортировать в JSON. Импортированный пакет можно импортировать повторно без изменений; экспортированный встроенный пакет служит только шаблоном — перед повторным импортом измените его `id` (id встроенных пакетов зарезервированы).
- **Встроенные пакеты по умолчанию**: три пакета входят в состав приложения:
  - `fyf.appearance.classic` — классический синий внешний вид
  - `fyf.search.balanced` — сначала релевантность, 50 результатов на странице, многоязычный поиск
  - `fyf.workflow.quicklaunch` — быстрые действия обслуживания
  Встроенные пакеты можно включать и отключать, но **нельзя удалить или перезаписать** (их id зарезервированы).
- **Хранение**: импортированные пакеты находятся в `components/packages/<id>.json` каталога данных приложения, состояние включения — в `components/state.json`.

## 6. Ограничения безопасности

1. Пакеты компонентов **декларативны**: они не содержат скриптов, исполняемых файлов и ссылок на удалённые ресурсы, и хост никогда не выполняет строки из пакета.
2. Один файл — не более 1 МиБ, конфигурация одного компонента — не более 256 КиБ, компонентов в пакете — не более 32.
3. Идентификаторы пакетов должны быть уникальными; id встроенных пакетов занимать нельзя.
4. Неизвестные поля и неизвестные `kind` игнорируются или показываются только для чтения и не приводят к сбою приложения.

## 7. Минимальный пример: собственная фиолетовая тема

```json
{
  "schema": 1,
  "id": "com.example.violet-theme",
  "name": "紫色夜间",
  "version": "1.0.0",
  "description": "紫色强调色 + 减弱动效",
  "author": "example",
  "kind": "theme",
  "components": [
    {
      "id": "appearance",
      "kind": "theme",
      "title": "Violet",
      "config": { "accent": "violet", "font_scale": "normal", "reduce_motion": true }
    }
  ]
}
```

Сохраните файл как `violet-theme.json` и импортируйте его в приложении.
